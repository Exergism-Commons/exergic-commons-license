## CODEX-0.3-028 — P2 — Parse and validate the review timestamp

**Finding.** The content-addressed compatibility evidence required a non-empty `reviewed_at` string but did not parse it. An arbitrary value such as `not-a-date` could therefore authorize a `complete` state. Conversely, PyYAML materializes ordinary unquoted YAML dates/timestamps as `date`/`datetime` objects, so legitimate evidence could be rejected merely because the YAML loader typed the scalar.

**Disposition: resolved in candidate.**

- `tools/render_schedule.py` now validates `reviewed_at` explicitly rather than testing string non-emptiness.
- String values must be either a valid ISO calendar date (`YYYY-MM-DD`) or an RFC 3339 timestamp with an explicit `Z` or `±HH:MM` timezone.
- Impossible dates, arbitrary strings, timestamps using the wrong lexical separator, and timezone-less timestamp strings are rejected.
- PyYAML `date` values are accepted directly.
- PyYAML `datetime` values are accepted only when timezone-aware; naïve datetimes are rejected.
- `tools/test_schedule_compatibility_gate.py` covers valid ISO/RFC 3339 strings, YAML date/datetime scalar types, impossible/malformed values, timezone-less values, and the full content-addressed evidence path for both a valid YAML date scalar and an invalid timestamp.
- `reviews/schedule-compatibility/README.md` now states the exact accepted timestamp/date contract.
