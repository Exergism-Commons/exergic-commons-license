## CODEX-0.3-029 — P2 — Reject out-of-range RFC 3339 time fields

**Finding.** Pass 16 began parsing `reviewed_at`, but its lexical pattern still accepted out-of-range clock and timezone fields. Python/PyYAML can normalize malformed values such as `+01:60` or `+00:99`, so relying on `datetime.fromisoformat()` after construction could erase the malformed original representation and allow it to authorize a future `complete` compatibility state.

**Disposition: resolved in candidate.**

- `tools/render_schedule.py` now range-binds RFC 3339 clock and numeric-offset fields lexically: hours `00`–`23`, minutes `00`–`59`, seconds `00`–`60` (RFC 3339 leap-second grammar), and offset hours/minutes `00`–`23` / `00`–`59`.
- Calendar validity remains checked independently with `date.fromisoformat()`.
- The renderer now inspects the original YAML `reviewed_at` scalar with `yaml.compose()` before `safe_load()`, so malformed values cannot be normalized into a different apparently valid `datetime` before validation.
- The ordinary semantic `date` / timezone-aware `datetime` acceptance from pass 16 remains in place after lexical validation.
- Regression coverage rejects the exact Codex reproductions `2026-08-15T24:00:00Z`, `2026-08-15T00:00:00+01:60`, and `2026-08-15T00:00:00+00:99`, including as unquoted timestamp scalars inside real content-addressed evidence files. It also covers minute/second/offset-hour overflow.

This hardens repository evidence parsing only; it does not turn automated review into qualified legal review.
