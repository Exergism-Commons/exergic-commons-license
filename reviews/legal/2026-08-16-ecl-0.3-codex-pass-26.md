## Finding

### CODEX-0.3-044 — P2 — copied bootstrap could redirect implementation selection

Codex reproduced a fresh bypass beyond CODEX-0.3-043. A literal copy, reflink, or equivalent regular-file replica of `tools/render_schedule.py` is neither a symlink nor a hardlink and can satisfy the prior `realpath == abspath` check. When that copied wrapper sits beside an attacker-controlled `render_schedule_impl.py`, supported `python -I -S <copy> --validate-only` execution can select and execute the attacker sibling before renderer-environment or compatibility-evidence validation.

## Resolution

The bootstrap no longer treats its own containing directory as sufficient authority to choose the implementation. After import search has been reduced to interpreter-owned roots, it:

1. rejects symlink and hardlink aliases as before;
2. resolves the physical wrapper path;
3. discovers the containing ECL checkout using multiple repository-specific canonical sentinels;
4. requires the executing wrapper to be exactly `<repository-root>/tools/render_schedule.py`;
5. derives the implementation only as `<repository-root>/tools/render_schedule_impl.py` after that identity check;
6. rejects a non-canonical or missing implementation path before opening it.

`tools/test_schedule_compatibility_pass26.py` reproduces the literal-copy attack with a marker-emitting sibling implementation, plus a nested `tools/`-shaped copy intended to resemble the canonical layout. Both must fail before the marker executes. Canonical repository execution remains required to succeed. Both Schedule workflows trigger on and execute the pass-26 regression.
