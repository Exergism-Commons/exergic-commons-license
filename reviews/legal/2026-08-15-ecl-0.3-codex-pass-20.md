## Findings

### CODEX-0.3-034 — P2 — Require string keys before duplicate detection

The recursive compatibility-evidence YAML pre-pass compared raw scalar-node text for duplicate detection while allowing non-string scalar key tags. PyYAML `SafeLoader` can construct lexically distinct keys as equal Python keys, including examples such as `1`/`true`, `01`/`1`, and `null`/`~`. A content-addressed record could therefore pass the lexical pre-pass and then be collapsed under last-key-wins semantics during `safe_load()`.

**Disposition:** fixed. Every mapping key at every depth of a compatibility-evidence document must now be a scalar using the standard YAML string tag. Numeric, boolean, null, timestamp, merge, custom, or otherwise non-string key tags are rejected before construction. Existing recursive duplicate-key, merge-key, alias, and unsupported-tag guards remain in force. Regression coverage exercises the exact SafeLoader key-collision families through the real content-addressed `complete` evidence path and verifies that an explicitly quoted numeric-looking string key remains a string key.

### CODEX-0.3-035 — P2 — Bind follow resolution to the channel's Bundle ID

`resolve_follow()` loaded `releases/bundles/<channel bundle ref>.json` but, unlike `resolve_pinned()`, did not verify that the manifest's internal `bundle` field equalled the channel-selected Bundle ID. A channel could therefore advertise Bundle `X` while the file at `X.json` self-declared otherwise-valid Bundle `Y`, after which resolution could validate and render a lock for `Y`.

**Disposition:** fixed. `resolve_follow()` now binds filesystem lookup, channel `bundle` reference, and manifest `bundle` identity before operative-state, major-version, component, or legal-review validation. The same `bundle manifest identity mismatch` invariant is therefore enforced in pinned and follow modes. `tests/test_ecl_resolve.py` contains a regression where a channel selects one Bundle ID while the corresponding manifest declares another and requires rejection before resolution.

Mechanism commits include `f930ed9537a5872eab7006feef84957376bc3f3f` and `7b5672ec4b3bc1215a4ed8fb3ffc0dd5efe7e3c5`.
