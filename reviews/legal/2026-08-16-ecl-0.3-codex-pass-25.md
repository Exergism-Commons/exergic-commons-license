## CODEX-0.3-043 — P2 — bootstrap filesystem alias could redirect renderer implementation

Codex reviewed exact HEAD `7cfd1212c1d290da4154a331479f0d3c67b2bd61` and found that the isolated Schedule bootstrap derived `render_schedule_impl.py` from the lexical `__file__` directory before resolving the wrapper's physical location. Invoking the reviewed wrapper through a filesystem symlink such as `alt/render_schedule.py -> ../tools/render_schedule.py` therefore allowed an attacker-controlled `alt/render_schedule_impl.py` to be opened and executed before renderer-environment or compatibility-evidence validation.

### Disposition

Accepted as valid. The bootstrap now keeps only interpreter-owned import roots first, then imports filesystem helpers from that sanitized environment. Before selecting the implementation it rejects symlink invocation, rejects bootstrap hardlink aliases, resolves the wrapper to a canonical physical path, and derives the implementation sibling only from that canonical wrapper path. The implementation is therefore no longer selected from an attacker-controlled symlink directory.

`tools/test_schedule_compatibility_pass25.py` reproduces the reported symlink attack with a malicious sibling implementation and requires rejection before the marker can execute. It also attacks the equivalent hardlink alias and verifies that the canonical reviewed wrapper still executes successfully. Both Schedule workflows trigger on and execute the pass-25 regression under isolated Python while continuing to execute the renderer itself as `python -I -S tools/render_schedule.py ...`.

The Schedule compatibility pointer remains `pending`. No ECL-0.3-DRAFT compatibility evidence has been fabricated or inferred from this technical hardening.
