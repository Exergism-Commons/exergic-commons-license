## Finding

### CODEX-0.3-045 — P2 — repository sentinel presence did not authenticate implementation bytes

Codex reproduced a fresh bypass beyond CODEX-0.3-044. A literal copy of `tools/render_schedule.py` placed at `fake-root/tools/render_schedule.py` could be surrounded by the five repository-root sentinel paths expected by the bootstrap. Because the pass-26 root check authenticated only path shape/file presence, that spoofed root was accepted and the copied wrapper then selected and executed attacker-controlled `fake-root/tools/render_schedule_impl.py` before renderer-environment or compatibility-evidence validation.

## Resolution

Repository shape is no longer the authority for executable implementation bytes. After the existing `-I -S`, interpreter-owned import-root, symlink/hardlink, canonical wrapper-path and repository-slot checks, the reviewed bootstrap now:

1. carries the exact Git blob identity of the reviewed `tools/render_schedule_impl.py` as an immutable bootstrap trust anchor;
2. reads the candidate implementation once as raw bytes;
3. reconstructs the Git blob frame (`blob <length>\0<bytes>`) and verifies its exact object identity before compilation or execution;
4. rejects any sibling implementation whose bytes differ from the reviewed implementation;
5. decodes and executes the same authenticated in-memory bytes, rather than reopening the path after verification, so the authentication/execution step has no separate file reopen TOCTOU window.

The fixed object is `d266a52f5c040c3b5e865b8b6592553ae20770d9`, the Git blob identity of the reviewed implementation bytes. This is a fixed-object second-preimage trust boundary rather than a generic attacker-selected collision scenario. The later compatibility-evidence mechanism continues to bind the exact bootstrap and implementation files by SHA-256; changing either code artifact therefore still invalidates completed compatibility evidence by design.

`tools/test_schedule_compatibility_pass27.py` reproduces the reported complete fake-root sentinel set plus copied wrapper and marker-emitting malicious implementation. The invocation must fail on implementation-byte authentication and the marker must never execute. It also requires canonical repository execution to continue succeeding and asserts that the bootstrap authenticates and executes one identical byte buffer. Both Schedule workflows trigger on and execute the pass-27 regression.
