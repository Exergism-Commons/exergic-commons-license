## CODEX-0.3-030 — P2 — Reject duplicate `reviewed_at` keys

Codex found that the lexical guard returned the first top-level `reviewed_at` node while `yaml.safe_load()` retained the last duplicate key. A content-addressed evidence file could therefore place a valid first timestamp followed by a malformed unquoted timestamp whose offset PyYAML normalized; the lexical guard and semantic validator would inspect different effective values.

### Disposition

Accepted and fixed.

The evidence root mapping is now structurally validated before `safe_load()`. Every top-level key must be scalar and unique; duplicate keys are rejected rather than inheriting PyYAML's last-value-wins behavior. Root YAML merge keys (`<<`) are also rejected. The same structural pass returns the single original `reviewed_at` scalar for lexical validation, so lexical and semantic validation cannot silently target different duplicate values.

Regression coverage constructs real content-addressed evidence with a valid first `reviewed_at` followed by malformed `+01:60` and requires rejection before semantic loading.

## CODEX-0.3-031 — P2 — Reject impossible leap-second timestamps

Codex found that accepting a seconds field of `60` as syntactically RFC 3339-compliant permitted impossible values such as `2026-08-15T12:34:60Z` to authorize a completed compatibility record. Proper acceptance would require proving that the resulting UTC instant is an actual leap-second insertion.

### Disposition

Accepted and fixed.

The compatibility gate deliberately rejects `second == 60` entirely. This avoids embedding or depending on a mutable historical leap-second table in repository-integrity code. Accepted timestamp strings therefore use seconds `00` through `59`; otherwise callers may use an ISO calendar date.

Regression coverage rejects arbitrary `:60` timestamps directly and through the real content-addressed evidence path.

## Result after patching

The gate now combines:

- content-addressed evidence bytes and canonical path/ID identity;
- exact target-License and complete source-set SHA-256 binding;
- original-YAML lexical timestamp validation before PyYAML construction;
- explicit clock/offset ranges;
- no leap-second acceptance without external insertion evidence;
- unique scalar top-level evidence keys with no YAML merge keys; and
- semantic validation after loading.
