## CODEX-0.3-032 — P2 — Reject duplicate keys in nested evidence mappings

### Finding

The pass-18 structural pre-pass rejected duplicate and merge keys only in the
root evidence mapping. Nested mappings such as `target_license_artifact` and
individual `sources` entries could still rely on PyYAML last-key-wins or merge
semantics. That permitted the exact content-addressed bytes to contain a stale or
misleading first `path`/`sha256` followed by a valid duplicate value that the
semantic checks would ultimately retain.

### Resolution

`tools/render_schedule.py` now validates the complete YAML node tree before
`safe_load()`:

- every mapping at every depth requires scalar, unique keys;
- YAML merge keys (`<<`) are rejected recursively;
- YAML aliases are rejected so one composed node cannot populate multiple
  semantic positions;
- mapping, sequence, key, and scalar nodes are restricted to the standard YAML
  tags admitted by the evidence format; and
- the original `reviewed_at` scalar is extracted only after the complete tree
  passes that structural validation.

Regression coverage constructs nested duplicate `path` keys and nested merge
keys inside `target_license_artifact`, and also attacks aliases and custom tags.

## CODEX-0.3-033 — P2 — Reject quoted whitespace around review timestamps

### Finding

`validate_reviewed_at()` stripped string values before lexical validation. A
quoted YAML scalar such as `" 2026-08-15T00:00:00Z "` therefore passed even
though the effective YAML string was not itself the documented ISO-date/RFC3339
lexical value.

### Resolution

String `reviewed_at` values are now validated exactly as stored. No leading or
trailing whitespace is trimmed or otherwise normalized. Typed PyYAML `date` and
timezone-aware `datetime` values remain accepted under the existing rules.
Regression coverage rejects leading/trailing whitespace directly and through a
real content-addressed completed-evidence path.
