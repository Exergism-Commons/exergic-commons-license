## CODEX-0.3-041 — P2 — Bind/prevent repository-local shadow imports

### Finding

The renderer bound `tools/render_schedule.py` and the exact PyYAML pin, but direct execution with `python tools/render_schedule.py` prepended `tools/` to Python's import search path before the renderer imported `hashlib` and `yaml`. A later sibling such as `tools/hashlib.py` or package `tools/yaml/` could therefore shadow the intended implementation. Such a file was outside the compatibility source set and both Schedule workflow path filters, so the old `complete` evidence could remain apparently valid while hashing or YAML construction semantics changed. A shadow package could even report the expected `yaml.__version__`.

### Disposition

Fixed by eliminating the demonstrated import path rather than attempting to enumerate an open-ended dependency closure.

- `tools/render_schedule.py` is now a minimal bootstrap. Before loading any shadowable module it imports only built-in `sys` and removes the repository `tools/` directory from `sys.path` while the implementation's complete top-level import set is resolved.
- The previous renderer implementation is preserved byte-for-byte as `tools/render_schedule_impl.py`.
- The bootstrap rejects repository-local `hashlib` or `yaml` origins if a host process had already supplied such a module.
- `schedule_renderer_control_paths()` now binds **both** `tools/render_schedule.py` and `tools/render_schedule_impl.py`, so any future bootstrap or implementation change invalidates old compatibility evidence.
- Both Schedule workflows trigger on the implementation and pass-23 regression file.
- `tools/test_schedule_compatibility_pass23.py` creates the exact sibling `tools/hashlib.py` and `tools/yaml/` attack shapes in isolated test runs and requires direct renderer execution to ignore them. It also asserts that both renderer code artifacts are present in the compatibility control set.

This is deliberately narrower than pinning the entire interpreter/OS/runner image: the proven semantic bypass was repository-local import shadowing, and that path is now removed and regression-locked.

The Schedule compatibility pointer remains **pending**. No compatibility evidence or legal review has been fabricated.
