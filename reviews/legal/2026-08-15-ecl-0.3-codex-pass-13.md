## CODEX-0.3-024 — P2 — Validate 0.3 compatibility before relabeling Schedule output

**Finding.** After CODEX-0.3-023 aligned the mutable draft channel and Schedule-facing labels with the working `ECL-0.3-DRAFT`, the frozen registry inputs consumed by `tools/render_schedule.py` still declared `compatible_license: "ECL-0.2-DRAFT"`. The renderer did not read or validate that metadata, so it could emit an `ECL 0.3-DRAFT only` compatibility label for clauses whose freeze/review evidence had only established compatibility with 0.2. Green Schedule CI therefore did not prove the advertised 0.3 compatibility.

**Disposition: resolved in candidate without fabricating revalidation.**

- `tools/render_schedule.py` now defines the target working License separately from source compatibility evidence.
- It inventories every frozen clause source it can render: the R-state freeze, all State-S freeze files, organization/armed-organization freezes, and project freezes.
- Every such source must carry a non-empty `compatible_license` declaration; missing metadata is a validation error.
- Source declarations alone are not enough to upgrade compatibility. `registry/schedule-license-compatibility.yml` is a second explicit revalidation gate, currently and honestly `status: pending` for `ECL-0.3-DRAFT`.
- A future `complete` compatibility record must have a non-empty review ID and bind **the entire exact renderer-consumed source set** by repository-relative path and SHA-256. Missing, extra, duplicate or stale bindings are rejected.
- The renderer may emit an `Intended compatibility: ECL-0.3-DRAFT only` label only if every consumed frozen source declares exact target compatibility **and** the explicit compatibility record is complete and hash-valid.
- With the repository's present evidence, generated candidates instead state: target `ECL-0.3-DRAFT`, compatibility **NOT YET VALIDATED**, source-declared compatibility `ECL-0.2-DRAFT`, and explicit hash-bound revalidation **PENDING**.
- No registry freeze was mechanically relabelled from 0.2 to 0.3. Advancing those declarations requires an actual compatibility revalidation.
- `schedules/ECL-RP-0.5-PARTIAL-DRAFT.md` makes the same distinction and explicitly lists source revalidation as a prerequisite for a complete candidate.
- Both `Schedule integrity` and `Schedule release readiness` assert the pending-compatibility state and fail if an ECL-0.3-DRAFT compatibility label is emitted prematurely.
- The generic regression test requires the same target-vs-evidence distinction without adding PyYAML to unrelated test environments.
