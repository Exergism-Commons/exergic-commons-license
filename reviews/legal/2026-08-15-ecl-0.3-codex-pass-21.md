## CODEX-0.3-036 — P2 — Include renderer control inputs in compatibility evidence

### Finding

The content-addressed Schedule compatibility record bound frozen clause files but did not bind every input that controls which clauses the renderer actually emits. In particular, `registry/states.yml`, `registry/state-outcome-overrides*.yml`, and `registry/schedule-status-overrides.yml` feed `state_outcomes()` / `status_blocked_states()` and can materially change the generated Schedule while old compatibility evidence would still validate.

### Disposition

Fixed. The renderer now distinguishes clause sources from the complete compatibility input set. A completed compatibility review must bind, by exact path + SHA-256:

- every frozen Schedule clause source;
- `registry/states.yml`;
- every currently matching `registry/state-outcome-overrides*.yml`;
- `registry/schedule-status-overrides.yml` when present; and
- the exact bytes of `tools/render_schedule.py` itself.

The dynamic glob is part of the expected set, so adding or removing an outcome-overlay file also invalidates old evidence. Binding the renderer implementation additionally prevents an algorithm change from silently reusing evidence reviewed against older selection/rendering semantics.

Regression coverage proves that clause-only evidence no longer equals the complete renderer input set and that `compatibility_status()` supplies the full set to the immutable-evidence gate.

## CODEX-0.3-037 — P2 — Traverse YAML mapping keys when rejecting aliases

### Finding

The alias detector tracked recursively visited YAML value/sequence nodes but mapping key nodes were inspected only for type/tag/text. An anchored scalar could therefore be reused later as a mapping key and escape the claimed alias-free node-identity traversal.

### Disposition

Fixed. Every mapping key is now recursively visited through the same `seen_nodes` identity set used for values and sequence items, after enforcing scalar/string-key and merge-key rules. Reuse of an anchored key/value node in key position or reuse of a key node in value position is rejected as a YAML alias.

Regressions cover both directions:

- anchored value reused as a mapping key; and
- anchored mapping key reused as a value.
